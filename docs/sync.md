# Shared data and offline behavior

The app uses the desktop server's protocol 1: `/v1/login`, `/v1/snapshot`, `/v1/changes`, `/v1/batches`, `/v1/logout` and admin `/v1/users`. Server/desktop source belongs to the separate `pcpapc172/laptops` repository.

SQLite stores canonical rows with UUIDs, revisions and tombstones, plus an atomic outbox of exact immutable transaction payloads. Views project pending changed-field patches over the canonical cache. Counter updates merge as positive deltas. Each later local operation references the earlier mutation's receipt where necessary. Uploads replay the same transaction ID and body after errors; own committed transactions in the feed resolve a lost acknowledgement before a pending counter can be applied twice. The feed cursor is advanced only by pulls, never by an upload response.

Forms compare with the values shown when opened and patch only intended fields onto current cached data. The server's 4.0 policy applies normal edited fields to the current record. Quantities, role permissions, references and active laptop uniqueness remain enforced. Server rejection preserves the complete local proposal in the conflict list. Retry uses a fresh transaction ID; discard keeps the original proposal in the local journal. Server restoration into another instance epoch quarantines pending work for review.

Foreground uploads happen after a local commit and incoming changes are polled every ten seconds. Transient failures use bounded exponential backoff. Network restoration triggers another foreground cycle. Pending work also schedules Android JobScheduler with a network requirement; background timing depends on Android's battery/background policy. Background uploads use a Keystore-protected session token; an expired session without an in-memory password requires a fresh login. Pending operations remain intact.

Every new app process begins at the password gate. Online login establishes a random-salted PBKDF2-HMAC-SHA256 verifier with 600,000 iterations and a seven-day lease. The password itself is never stored. Android Keystore AES-GCM protects the saved session token. Network failure may offer offline access with the same account/password. Authentication rejection and TLS failure do not permit an offline bypass. Failed offline attempts are throttled; successful offline login never extends the original online lease. Logout revokes/clears the token and hides records while preserving offline verification and the outbox; confirmed account revocation invalidates the verifier.

The SQLite cache is in app-private storage and is not additionally encrypted. Android backup is disabled. Production HTTPS uses platform certificate/hostname validation; redirects and certificate bypasses are disabled. The test-only loopback transport option does not override Android's manifest prohibition on cleartext traffic.

Build references: [Android Gradle Plugin compatibility](https://developer.android.com/build/releases/agp-8-13-0-release-notes), [Android Keystore](https://developer.android.com/privacy-and-security/keystore), [offline-first architecture](https://developer.android.com/topic/architecture/data-layer/offline-first).
